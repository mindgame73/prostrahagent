# ПроСтрахАгент — прелендинг для перелива трафика в Telegram

Статичный сайт без сборки: `index.html`, `styles.css`, `script.js`, `config.js`, `favicon.svg`,
плюс `consent.js` (баннер cookie), `privacy.html` / `consent.html` + `docs.js` (документы по 152-ФЗ) и `fonts/` (шрифты лежат локально, без Google Fonts).
Кнопки «Стать агентом» ведут в Telegram-канал. Для клиентов есть блок «Рассчитать страховку» (`#policy`) с виджетом Инссмарт (вкладки ОСАГО / страхование ипотеки) и кнопкой «Написать менеджеру» — она ведёт на `manager` из `config.js`, а пока он пуст — в канал.

## Виджет Инссмарт

Создан в кабинете агента: agents.inssmart.ru → Инструменты продаж → Виджет («ПроСтрахование», домен prostrahagent.ru). Код вставки (`data-token`, `data-secret`) стоит в `index.html` внутри `#inssmartWidget`. Вкладки задают `data-product` (`/eosago`, `/mortgage`) — `script.js` пересоздаёт скрипт виджета при переключении. Если в кабинете перевыпустили ключи — обновите их в `index.html`.

Страницы продуктов для поиска: `/osago/`, `/ipoteka/`, `/travel/` — заголовок, калькулятор на нужном продукте, «что понадобится», вопросы, ссылки на другие продукты и блок «Стать агентом». Они собираются скриптом из шапки/подвала/виджета главной: тексты правьте в `tools/build_pages.py`, затем `python3 tools/build_pages.py .` (не правьте `*/index.html` руками — перезапишется). Новые страницы добавляйте и в `sitemap.xml`.

Ссылки сразу на нужный калькулятор (для рекламы и постов): `prostrahagent.ru/#osago`, `#mini-kasko`, `#ipoteka`, `#kvartira`, `#travel`, `#antiklesh`, `#titul`; `#kasko` открывает блок «через менеджера» (КАСКО в виджете Инссмарт недоступен).

Виджет сам прокручивает страницу при смене шага/поля — инлайн-скрипт перед виджетом в `index.html` перехватывает эти команды и прокручивает, только если поле вне экрана.

После правок `styles.css` / `script.js` поднимайте `?v=` в `index.html`, иначе браузеры возьмут старую версию из кэша GitHub Pages.

## Настройка — `config.js`

| Поле | Что это |
|---|---|
| `telegram` | Ник канала без `@`. Все кнопки ведут сюда |
| `manager` | Ваш ник для связи — появится кнопка «Написать нам» |
| `owner` | Оператор персональных данных: `name` (ФИО или «ИП …»), `inn`, `email`. Показывается в подвале и подставляется в политику и согласие — пока не заполнено, там жёлтые плашки «заполните …» |
| `rewards` | Вознаграждение за полис для калькулятора (ОСАГО / КАСКО / ипотека) — сверьте с кабинетом |
| `inviteLinks` | Отдельные инвайт-ссылки канала под кампании/источники (ключ = `utm_campaign` или `utm_source`, плюс `default`). В статистике ссылок в Telegram видно, сколько подписчиков дал каждый источник |
| `bot` | Ник бота. Если задан, кнопки ведут в `t.me/<bot>?start=<click_id>`: бот получает click_id и может слать постбэк при подписке |
| `postbackUrl` | Постбэк в трекер при клике «в Telegram», `{click_id}` подставится |
| `metrikaId`, `vkPixelId` | Яндекс.Метрика и пиксель VK Рекламы |

Приоритет: `bot` → `inviteLinks` → `telegram`.

## Cookie и персональные данные

- Если задан хотя бы один из `metrikaId`, `vkPixelId`, `postbackUrl`, внизу появляется баннер «Принять / Отклонить» и ссылка «Настройки cookie» в подвале.
- До «Принять» Метрика и пиксель VK не загружаются, постбэк не уходит, метки не сохраняются между визитами. После «Отклонить» сайт стирает их записи (`_ym*`, `_tmr*`, `ps_track`).
- Если ни один из них не задан, сайт не ставит cookie и ничего не пишет в браузер: политика показывает режим «на сайте данные не собираются», ссылка на текст согласия скрыта.
- Блоки в `privacy.html` / `consent.html` с `data-if="metrikaId"`, `data-if="tracking"`, `data-if="!tracking"` и т.п. показываются по `config.js` — политика описывает ровно то, что подключено.
- Если собираете в Telegram телефоны/заявки (личка, бот) — это тоже обработка ПДн: дайте человеку ссылку на политику до того, как спрашивать контакты.
- Уведомление об обработке ПДн в Роскомнадзор (pd.rkn.gov.ru) подаётся отдельно, сайт его не заменяет.

## Метки

Берутся из URL: `utm_*`, `sub1`, `sub2`, `click_id` (также `clickid`, `subid`, `yclid`, `gclid`, `vkclid`, `fbclid`) и запоминаются в браузере.

Цели: `tg_click` — любой переход в TG; по кнопкам — `tg_header`, `tg_hero`, `tg_calc`, `tg_geo`, `tg_main`, `tg_sticky`, `tg_footer`, `tg_faq`, `tg_mockup`, `tg_manager`, `tg_policy_manager` (кнопка «Написать менеджеру» у виджета).
